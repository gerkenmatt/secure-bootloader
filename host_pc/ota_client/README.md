# BLE OTA Client

This directory contains the interactive command-line client for performing manual Over-the-Air (OTA) updates to a device running the secure bootloader. The client communicates with the device over Bluetooth Low Energy (BLE).

## 1. Overview

The `ble_ota_client.py` script is a host-side tool that provides an interactive terminal for a developer to manually initiate and monitor the OTA update process. It handles device discovery, connection, and the implementation of the bootloader's custom OTA protocol.

### Key Functionality

* **Device Discovery**: Scans for and connects to the target BLE device by its advertised name.
* **Interactive CLI**: Provides a simple command prompt for sending commands to the bootloader.
* **Smart OTA Updates**: The `update <name>` command automatically queries the device for its currently active slot and sends the correct firmware file to update the *inactive* slot.
* **Protocol Handling**: Implements the `SOF/EOF`-wrapped frame protocol, including CRC32 checks and ACK/NACK handling.
* **Live Logging**: Displays real-time log messages and status updates received from the device.

## 2. Directory Structure

The client expects a specific directory structure to locate the firmware files it needs to send.

```
.
├── ble_ota_client.py    # The main client script.
└── firmware/            # INPUT: Directory containing all signed firmware binaries.
  ├── blinky_slota.bin
  ├── blinky_slota.sig
  ├── blinky_slotb.bin
  ├── blinky_slotb.sig
  └── ...
```
The firmware files in the `firmware/` directory should be the final, signed artifacts generated by the scripts in the `../utilities/` directory.

## 3. Prerequisites

1.  **Hardware**: An STM32 device must be connected and flashed with the secure bootloader firmware.
2.  **Firmware Artifacts**: The `firmware/` directory **must be populated** with the signed binaries and signature files. You should generate these using the scripts in the `../utilities` directory and copy them here.
3.  **Python Environment**: A working Python 3 installation is required. It is highly recommended to use a virtual environment.

## 4. How to Use the Client

### Step 1: Set Up the Environment

If you haven't already, create a virtual environment and install the required packages.

```bash
# (From the host_pc directory)

# Create a virtual environment (if you haven't already)
python3 -m venv .venv
source .venv/bin/activate

# Install dependencies
pip install -r requirements.txt
```

### Step 2: Populate the Firmware Directory
Ensure the firmware/ subdirectory within this folder contains the signed firmware you wish to send. The file names should follow the pattern <name>_slota.bin, <name>_slota.sig, etc.

### Step 3: Launch the Client
Run the script from your terminal. It will automatically start scanning for the target device.
```bash
# (From the host_pc/ota_client directory)
python3 ble_ota_client.py
```
### Step 4: Interact with the Client CLI
Once connected, you will see a `➜` prompt. The following commands are available:

- `update <name>`: This is the primary command. It initiates a full OTA update sequence.
  - `<name>` should be the base name of the firmware you want to send (e.g., `blinky`, `uart_print`).
  - The script will first send a `status` command to the device to determine the active slot.
  - It will then automatically select the correct binary/signature pair for the inactive slot and perform the update.
  - Example: `update blinky`
- `status`: Sends a command to the device to report its currently active slot
- `help`: list other useful commands
- `quit`: Disconnects from the device and exits the client
